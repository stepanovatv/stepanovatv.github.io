# Проверка MVP

Проверки выполнены 17–18 сентября 2026 года на Apple Silicon macOS со Swift 6.2.3.

## Автоматические проверки

- Web: `npm test` — 17 тестов. JSON, конфигурация, busy/free, миграция, IANA/DST, границы календаря, соседние исходные даты, cache busting, ошибки загрузки.
- Swift Core: `bash macOS/test.sh` — 16 тестов. Модель, календарь, сериализация, история действий, черновик, GitHub GET/PUT, конфликты SHA до записи и между GET/PUT, 422, ошибки сети и авторизации.
- Swift Editor: тот же скрипт — 12 тестов редактирования, фонового сохранения и загрузки ресурсов приложения. Единое состояние ячеек, повторное посещение, пересечение дней, один Undo/Redo на жест, диапазон с исключённым концом и запрет изменений во время сетевой операции. Проверены повторное использование разметки недели, обновление пачки ячеек одним событием, порядок фоновых записей, обработка ошибки диска и ожидание записи при выходе. Тестовые редакторы не имеют remote snapshot; тесты фоновой очереди используют подставную функцию записи. Реальные черновики, Keychain и GitHub не изменяются.
- Debug и release сборки прошли. Release `.app` имеет локальную ad-hoc подпись, проверенную `codesign --verify --deep --strict`.

## Проверка интерфейсов

В браузере проверены desktop и мобильная ширина 390 px: автоматическая зона Asia/Tbilisi, ручная Europe/Moscow, изменение времени без reload, недельная навигация, выбор и повторное снятие выделения, скрытая до выбора нижняя панель подробностей, запрет перехода раньше текущей недели, клавиатурные стрелки и подсветка строки/столбца.

В macOS 1.1.0 проверены значки состояний без повторяющегося текста, увеличенные подписи времени, новый зелёный цвет, переключение недель, запуск `.app`, реальное чтение нового JSON из ветки master, сетка Оренбурга, переключение ячейки, активация кнопки публикации, ⌘Z и возврат к состоянию без изменений. Существующий черновик открытого пользователем редактора сохранён. После проверочного клика, Undo и закрытия его содержимое и исходный remote snapshot сравнены с копией до проверки: различий нет.

Физическое mouse-drag через средство UI-автоматизации не удалось выполнить: оно вернуло `noWindowsAvailable`. Логика жеста покрыта тестами редактора; физический drag и полный VoiceOver-сценарий остаются пунктами ручной приёмки. Матрица отдельных Safari/Firefox/Edge и реальных iOS/Android-устройств не прогонялась.

## Исправление переноса на другой Mac — 1.1.1

После сообщения о сбое на Apple M1 с macOS Tahoe 26.2 найдена зависимость старого загрузчика `Bundle.module` от абсолютного каталога сборки. Артефакт содержал ресурс в `Contents/Resources`, а сгенерированный SwiftPM-код сначала искал его в корне `.app`, затем по пути машины разработчика.

В версии 1.1.1 ресурс загружается через `Bundle.main.resourceURL`. Проверены 28 Swift-тестов, включая чтение конфигурации из изолированного `.app`, отсутствие ресурса и повреждённый JSON. Сборка и проверка подписи прошли. Из готового ZIP извлечена копия во временную папку: её служебный запуск `--verify-package` успешно прочитал встроенные параметры без пользовательских настроек и Keychain. При удалении конфигурации в этой тестовой копии проверка вернула код 1 без аварийного завершения и без подстановки данных из каталога сборки.

Эта проверка подтверждает исправление загрузки ресурсов. Физический запуск именно на втором Mac ещё должен подтвердить владелец. Developer ID и notarization не добавлены; возможная блокировка Gatekeeper является отдельным вопросом.

## Обновление 1.2.0 — 23 сентября 2026

- Web: 20 тестов; Swift: 35 тестов, все прошли. Добавлены проверки правила выходных, пустого исключения, сохранения и копирования свободного выходного, Undo/Redo, границы года, исходного дня при конверсии через полночь/DST, чтения старых черновиков и строгой валидации v2.
- Добавлен тест чтения публичного расписания при недоступном Keychain. Авторизация публикации не менялась; запись по-прежнему требует token.
- На этом Mac сейчас macOS 27.0, Swift 6.4. Для debug/release явно выбран установленный SDK macOS 26.5 через `SCHEDULE_MACOS_SDK`: в SDK 27 не поставляется необходимый его реализации SwiftUI плагин SwiftUIMacros. Deployment target остаётся macOS 14.0, архитектура — arm64.
- В браузере локальная страница показывает новую неделю 28 сентября — 4 октября с занятыми субботой и воскресеньем. Старые явно сохранённые даты не изменены; сравнены с актуальным `master` от 23 сентября.
- В нативном приложении проверены отдельные доступные кнопки и открытие редактора диапазона / подтверждения копирования. После отмены действий и закрытия сохранённый черновик и remote snapshot совпали с копией до проверки.
- Иконка с полупрозрачным календарём визуально проверена; по замечанию владельца уменьшены белые блики и затемнена зелёная подложка. Иконка создаётся во всех размерах 16–1024 px, включена в `.app` и проверяется служебным запуском.
- Светлая тема установлена в SwiftUI и AppKit. Снимок нативного окна в этой среде получить не удалось: ScreenCaptureKit вернул ошибку захвата потока. Проверка элементов окна через accessibility сработала; визуальная приёмка всей темы на втором Mac остаётся ручной.
- Владелец подтвердил, что прежнюю ошибку `-10810` вызывал карантин Telegram и снятие `com.apple.quarantine` устранило её. По его решению Developer ID / notarization не настраиваются; установщик не создаётся. Обычный ZIP не гарантирует отсутствие карантина после скачивания.

Новый замер 23 сентября (Swift 6.4/macOS 27, с правилом выходных): подготовка новой недели 1,515 мс, повторное использование сетки при изменении слота 0,243 мс. Контрольные суммы совпадают со старым алгоритмом (156,555 мс на той же машине). Это вычисления без SwiftUI и диска.

## Измерение производительности

`bash macOS/benchmark.sh`, release-оптимизация `swiftc -O`, тот же Mac:

- Старый путь подготовки подписей новой недели: **78,140 мс** в среднем за 20 недель.
- Новый путь с единой разметкой недели: **0,657 мс** (те же даты и контрольная сумма).
- Повторное использование подписей при редактировании: **0,016 мс** в среднем за 1000 итераций.

Это замер подготовки данных, а не полной задержки от клика до изображения на экране. SwiftUI-отрисовка, инструменты UI-автоматизации и диск в микробенчмарк не входят. Фоновая запись и её порядок проверены отдельно тестами. Смена недели, изменение ячейки и Undo проверены в release-приложении.

## Публикация

Изменения размещены в `master` репозитория `stepanovatv/stepanovatv.github.io`. GitHub Pages отдаёт новую `schedule.html`; её JSON побайтово/семантически сопоставлен с опубликованным файлом. В браузере публичная страница показывает 182 окна текущей недели, из них 72 занятых. В двух перенесённых неделях всего 144 занятых окна.

Главная страница и 24 прочих исходных файла блога сохранены без изменения. Jekyll продолжает работать; добавлен только список исключений для файлов разработки.

Реальный PUT из macOS-приложения и сохранение PAT в Keychain не выполнялись: владелец решил настроить token позднее. GET к реальному репозиторию проверен; PUT и конфликты проверены через URLProtocol без внешних записей. Приложение не подписано Developer ID и не notarized; архив предназначен прежде всего для текущего Mac (Apple Silicon, macOS 14+).


## Обновление 1.3.0 — 24 сентября 2026

- 34 Swift-теста прошли после изменения загрузки: теперь обычное чтение и обновление не обращаются к Keychain вообще. Публикация сохраняет прежний путь авторизации. В реальном запуске получено «Расписание актуально» без окна доступа к токену.

- Проверено переключение слота, активация публикации и Cmd+Z; тестовое изменение отменено, публикация не выполнялась.
- Иконка оставлена из 1.2.0 по последнему указанию владельца. Сгенерированные 3D-варианты в приложение не входят.
