# Public Availability Schedule

Публичное расписание и нативный редактор для macOS 14+. Интерфейс на русском, исходная часовая зона — `Asia/Yekaterinburg` (Оренбург). Без backend, npm-зависимостей и Git-клиента в приложении.

## Этот репозиторий

Проект встроен в существующий Jekyll-блог `stepanovatv/stepanovatv.github.io`. Главная страница и публикации сохранены. Публичное расписание: **https://stepanovatv.github.io/schedule.html**. Данные: `/schedule.json`. Рабочая ветка: `master`.

При первоначальном переносе старые отметки из `schedule.html` (Москва) пересчитаны в Оренбург и применены **только к 14–27 сентября 2026 года**, по указанию владельца. После этой даты не заданные в JSON слоты свободны. Старый HTML заканчивался слотом 19:00 МСК (21:00 Оренбург); новый дополнительный слот 21:30–22:00 пока свободен, поскольку в исходнике его не было. Перед использованием проверьте этот последний интервал, особенно по выходным.

## Для преподавателя

1. Откройте **«Расписание занятий»**.
2. Дождитесь сообщения «Расписание актуально».
3. Нажимайте на окна или проводите мышью по нескольким окнам: все получат состояние первой ячейки после переключения.
4. Нажмите **«Опубликовать расписание»**.

⌘Z отменяет действие, ⇧⌘Z возвращает его. Перетаскивание, изменение диапазона и копирование недели отменяются целиком. Правый клик на заголовке дня позволяет занять или очистить день. В меню «Действия» есть изменение диапазона и копирование предыдущей недели. Стрелки клавиатуры перемещают фокус по сетке, пробел переключает окно.

Неопубликованные изменения автоматически сохраняются на этом Mac. При следующем запуске приложение восстановит черновик и проверит его против GitHub. При конфликте можно оставить черновик или явно загрузить новую версию. Загрузка заменит локальные изменения; автоматического слияния нет.

## Первичная настройка администратором

Параметры репозитория уже заданы в `macOS/Sources/ScheduleApp/Resources/repository-config.json`. Для другой установки задайте owner, repository, branch, schedulePath и pagesURL до сборки либо откройте **«Настройки разработчика»** через меню приложения или ⌥⌘,.

Один раз создайте fine-grained GitHub Personal Access Token с доступом **только к этому репозиторию**, permission **Contents: Read and write**, и подходящим сроком действия. Введите token в SecureField настроек приложения. Token сохраняется только в macOS Keychain (`app.publicavailability.schedule.github`) с доступностью `WhenUnlockedThisDeviceOnly`; не попадает в JSON, исходники, UserDefaults, черновики или Git. Не передавайте его в переписке.

При пустом поле сохраняется существующий token. Отдельный переключатель удаляет его из Keychain. Для общедоступного репозитория чтение работает без token; публикация требует token. GitHub-пароль не используется. SSH, которым разработчик может первоначально разместить проект, не заменяет API-token самого приложения.

Параметры и черновики лежат в `~/Library/Application Support/PublicAvailabilitySchedule/`. Каждый репозиторий, путь и ветка имеют свой черновик и свой Keychain account.

## Сборка и запуск

Требуются macOS 14+, Swift 6 с Swift Testing (например, Xcode 16+ либо актуальные Command Line Tools). Само приложение использует системные SwiftUI, Foundation и Security; внешних Swift-пакетов нет.

```bash
cd macOS
bash build-app.sh
open "build/Расписание занятий.app"
```

Скрипт собирает release `.app` для архитектуры текущего Mac и подписывает его локальной ad-hoc подписью. Для распространения на других Mac с обычным Gatekeeper-запуском требуется Developer ID signing и notarization. Для Intel Mac можно собрать тот же проект на Intel или настроить соответствующий target; прилагаемая сборка имеет архитектуру Apple Silicon.

Для разработки пакет можно открыть в Xcode: `macOS/Package.swift`.

## Локальный web-просмотр

```bash
npm start
```

Откройте http://127.0.0.1:4173/schedule.html. Node 20+ нужен только для сервера разработки и тестов. В браузере сборщик и Node не нужны. Сервер предназначен для проверки расписания; Jekyll-блог собирается отдельно штатным способом GitHub Pages. Открытие HTML напрямую через `file://` не поддерживается, потому что браузер должен загрузить JSON через HTTP.

## GitHub Pages

В Settings → Pages выберите **Deploy from a branch → master → /(root)**. GitHub Pages сохраняет существующую сборку Jekyll. **Не добавляйте `.nojekyll` в этот репозиторий:** это отключит сборку блога. Для смены рабочей ветки измените Pages source и branch в конфигурации приложения.

Страница `schedule.html`, папки `css`, `js`, значок `assets/calendar.svg` и `schedule.json` — статические файлы. Каталоги `macOS`, `tests`, `scripts`, `docs` исключены из Jekyll-сборки. Нативный редактор меняет через GitHub Contents API **только `schedule.json`**. Каждый PUT создаёт commit; GitHub Pages обновляет страницу после сборки. Успех в приложении означает сохранённый commit, а не завершённую сборку Pages; возможна задержка в несколько минут.

Для отдельного пустого репозитория можно переименовать `schedule.html` в `index.html`, скопировать только web-файлы и изменить Pages URL в настройках. Это не требуется для текущего блога.

## Модель и часовые зоны

`schedule.json` — единственный источник опубликованной доступности. Версия 1 хранит busy-starts для конкретных дат. Отсутствующий день или слот свободен **внутри настроенного рабочего интервала**. Вне него ячейки недоступны. Конец дня исключительный; слот имеет реальную длительность в минутах. Длительность 5–240 минут должна нацело делить рабочий день; формат даты `YYYY-MM-DD`, время `HH:mm`, `updatedAt` — ISO 8601 UTC. Поддерживаемый диапазон календаря: 1900–2100.

Страница использует IANA-базу браузера через `Intl.DateTimeFormat`. Для каждого окна сначала определяется UTC-инстант, затем местные дата и время посетителя. Неделя — понедельник–воскресенье по календарю посетителя. При построении захватываются соседние исходные даты, поэтому переход суток не теряет окна на границах недели. Нестандартные смещения, включая 30 и 45 минут, сохраняются.

Повторяющиеся часы при осеннем DST отображаются отдельными окнами с UTC-смещениями. Несуществующее исходное время весеннего перехода пропускается; busy-отметки такого времени не проходят валидацию. Формат v1 не хранит признак `fold`: неоднозначное исходное время означает первое вхождение. Для `Asia/Yekaterinburg` в текущих датах эта неоднозначность не возникает.

На телефоне отображается один день, подробности выбранного окна видны в нижней панели. На desktop — таблица с подсветкой строки, столбца и фокуса. Tab входит в таблицу; стрелки перемещают фокус, Enter/Space выбирают окно, Escape снимает выделение. Сайт не бронирует и не редактирует расписание.

Загрузка JSON использует `cache: no-store`, timestamp query и timeout 15 секунд. Это уменьшает вероятность старых данных; глобальное обновление CDN не мгновенно. Ошибки сети, HTTP и некорректный JSON дают понятное сообщение с повторной попыткой.

## Публикация и конфликты

Сервис получает содержимое и SHA из явно заданной ветки. Перед PUT ещё раз читает файл и сравнивает SHA с загруженной базой. В PUT передаётся **тот же исходный SHA**: изменение между GET и PUT будет отклонено GitHub. 409 считается конфликтом; при 422 дополнительный GET отличает гонку от отказа валидации. Черновик не очищается при ошибке. UI блокирует редактирование только на время сетевой операции.

## Структура

```text
schedule.html, schedule.json, css/, js/  — публичное расписание
macOS/Sources/ScheduleCore/
  Models/                              — формат и конфигурация
  GitHub/                              — REST API и проверка SHA
  Storage/                             — снимок черновика и история
  Utilities/                           — календарные операции
macOS/Sources/ScheduleApp/
  Views/, ViewModels/                   — SwiftUI и состояние редактора
  Storage/                             — Keychain и локальный диск
  Resources/                           — конфигурация без секретов
tests/, macOS/Tests/                    — unit tests
```

Строки public web выделены в `js/strings.js`, основные статусы macOS — в `Utilities/Strings.swift`. При добавлении локалей можно перенести SwiftUI-литералы в String Catalog. Модель версии 1 намеренно содержит только доступность: неизвестные поля, в том числе личные аннотации, отвергаются.

## Проверка

```bash
npm test
cd macOS
bash test.sh
```

Тесты покрывают JSON round trip, некорректные данные, свободные/занятые окна, конфигурацию сетки, перенос старого HTML, IANA-конверсию, границы суток/месяца/года, DST, дробные timezone, соседние даты недели, Undo/Redo, copy week, черновики, GitHub GET/PUT, SHA-конфликт до записи и гонку во время PUT, 422, отсутствие сети и авторизацию. API-тесты используют `URLProtocol`; реальные токены и запись на GitHub им не нужны.
